#120 fixture: link-reference definition placement with a condition-wrapped table tail.
Exercises the #120<->#122 interaction (#122 is a soft prerequisite).

The long link lives in the UNCONDITIONED "Core" row. The table's final logical row
("Enterprise") is wrapped in <!--condition:enterprise-->...<!--/condition-->. If the
definition for the Core link were placed naively inside the condition span it would vanish
whenever "enterprise" is Hidden -- silently breaking a reference from a still-visible row.

Behavior (implemented, encoded in expected.md):
  1. Condition tag lines (<!--condition:enterprise--> and <!--/condition-->) are preserved
     verbatim in place as in-table pass-through members (the #122 scanner behavior), and all
     rows -- above and below them -- are planned to one aligned width (Feature=10,
     Description=58).
  2. The Core link is rewritten to "[the setup documentation][table-config-1]" because its
     cell (89 chars) exceeds the default max-cell-width (78) and the rewrite brings it within
     budget (58 <= 78).
  3. The definition line is emitted AFTER the whole rendered table -- which ends with the
     <!--/condition--> close tag -- so it lands outside the condition span, separated by one
     blank line. Definitions are emitted after the fully rendered block, so an
     outside-condition link's definition always follows the close tag.

DESIGN NOTES: reference ID "table-config-1" from the table alias "#config" (see
i120-linkref-rewrite-basic NOTES for the shared ID/definition assumptions). Definition
placement after the close tag is the load-bearing behavior this case pins.
