Known limitation from docs/solutions/tooling-decisions/markdown-table-formatter-design-2026-05-09.md
("Row with more cells than the header (IndexError in the renderer)"), now resolved.

Before: plan_widths() computed n_cols from the header row (2), so a data row with
3 cells was passed unwidened to _render_row(), which indexed widths[2] and raised
IndexError -> exit 1, empty stdout.

Now: the table's column count is the widest row's, taken from
TableBlock.normalize_columns(); the header and separator widen to that count and
every row renders aligned. This is the benign "pad/render" repair, the same one
that already padded shorter rows.

The golden encodes that repair: the widened header/separator third column carries
an empty header label and a min_col_width-floored width sized to its widest data
cell ("extra" = 5).
